# Dissertation Plan (Simple Version)
## Phase 1 only: Introduction + Analysis

This plan is written in simple steps so you can follow it easily.

What we are doing now:
- Introduction chapter (~600 words)
- Analysis chapter (~2000 words)

What we are not doing yet:
- Design
- Testing and Evaluation
- Conclusions

---

## Your goal for this phase
By the end of this week, you should have:
1. A full Introduction draft
2. A full Analysis draft
3. A clear requirements list (functional + non-functional)
4. A basic risk register
5. A clean Harvard references draft

---

## Week plan (day by day)

## Day 1 - Build your structure
Do this first before writing full paragraphs.

Tasks:
- [ ] Create `Introduction` headings
- [ ] Create `Analysis` headings
- [ ] Add rough word targets under each heading

Use this structure:

Introduction
- Context
- Problem statement
- Aim and objectives
- Solution overview
- Chapter roadmap

Analysis
- How you gathered information
- Background and regulation
- Stakeholders and workflows
- Functional requirements
- Non-functional requirements
- Business case
- Risks and mitigation
- Legal / ethical / social issues
- Project plan summary

---

## Day 1-2 - Build evidence table
Take your proposal and map each important claim to a source.

Tasks:
- [ ] Highlight legal/compliance claims
- [ ] Highlight safety and efficiency claims
- [ ] Add source next to each claim
- [ ] Mark any weak claim to rewrite later

Output:
- One "claim -> source" table

---

## Day 2 - Write Introduction Draft 1
Write a first version. Keep it simple and clear.

Checklist:
- [ ] Explain the current problem in Irish hospitality
- [ ] Explain why this matters (safety + operations)
- [ ] State project aim and objectives
- [ ] Explain your solution at a high level
- [ ] End with one short roadmap sentence

Tip:
Avoid deep technical details here. Save that for Design later.

---

## Day 3 - Write "Analysis method"
Explain how you got your requirements.

Include:
- Interviews
- Brainstorming
- Staff observations
- Focus groups / questionnaires

Checklist:
- [ ] List stakeholder groups (kitchen, servers, managers, customers)
- [ ] Explain how notes were captured
- [ ] Explain limits/bias (small sample, one pilot venue, etc.)

---

## Day 3-4 - Build requirements baseline
Turn your ideas into clear, testable requirements.

Tasks:
- [ ] Write functional requirements (what system does)
- [ ] Write non-functional requirements (quality/security/performance)
- [ ] Label each one as Must / Should / Could
- [ ] Add 1 acceptance check for each Must item

Examples to include:
- Table status updates
- Order workflow
- Kitchen status and allergen flags
- Allergen acknowledgment capture
- Reservations
- Reviews

---

## Day 4 - Write legal/ethical section
Keep this practical, not too theoretical.

Checklist:
- [ ] Explain allergen information duties at ordering stage
- [ ] Explain GDPR basics relevant to your project
- [ ] Explain role-based access (who can see what)
- [ ] Define a simple retention/deletion rule (can refine later)

---

## Day 4-5 - Write business case + risks

Business case:
- [ ] Benefits (safety, consistency, traceability, speed)
- [ ] Costs (dev time, training, rollout)

Risk register:
- [ ] Risk
- [ ] Impact
- [ ] Likelihood
- [ ] Mitigation action

Key risks:
- Scope creep
- Not enough stakeholder input
- Legal interpretation mistakes
- Time pressure before deadline

---

## Day 5-6 - Write Analysis Draft 1
Now combine all analysis pieces into one chapter.

Checklist:
- [ ] Keep clear flow from problem -> evidence -> requirements
- [ ] Mention any idea you considered but dropped
- [ ] Link major requirements to supporting evidence

---

## Day 6 - Edit pass

Checklist:
- [ ] Remove repetition
- [ ] Keep terms consistent
- [ ] Check citation-to-reference matching
- [ ] Tighten long sentences

---

## Day 7 - Freeze Phase 1 outputs

You are done with this phase when:
- [ ] Introduction is complete
- [ ] Analysis is complete
- [ ] Requirements list is prioritized
- [ ] Risk register exists
- [ ] References are cleaned up

---
